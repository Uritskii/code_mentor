# Code Mentor — спецификация проекта (ДЗ 1)

## Тема
Наставник по коду: находит ошибки в решении студента, не выдаёт готовый код,
а ведёт к решению ступенчатыми подсказками. Запоминает типичные ошибки студента.

## Пользователь
Студент, изучающий программирование. Присылает решение задачи в чат,
ждёт разбора ошибок и подсказок, а не готового ответа.

## Сценарий
1. Студент выбирает задачу и присылает код решения.
2. Агент запускает код на тестах (инструмент), анализирует ошибку.
3. Агент даёт подсказку уровня 1 (направление, без кода решения).
4. Студент правит код, цикл повторяется; уровень подсказок растёт.
5. Агент записывает типичные ошибки в профиль студента (действие).

## Инструменты (3)
| Инструмент | Тип | Что делает |
|---|---|---|
| `get_task` | чтение | Возвращает условие задачи по id |
| `run_tests` | чтение | Запускает код студента на тестах, возвращает агрегат без эталонных ответов |
| `record_mistake` | действие | Записывает категорию ошибки в профиль студента |

## Ключевое архитектурное решение
Эталонные ответы тестов НЕ попадают в контекст модели (их не возвращает
ни один инструмент) — утечка решения невозможна архитектурно, а не промптом.

## Данные
Учебные задачи с тестами (tasks.json), синтетические. В перспективе — RunBugRun.

## Провайдеры модели
Переключаются через переменную окружения PROVIDER: zai (GLM), groq, openrouter,
ollama (локально), gigachat. Один OpenAI-совместимый клиент, разные base_url.
